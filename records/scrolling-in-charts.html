Scrolling in charts

A dashboard tile never scrolls. The full list lives on the detail page, where the page scrolls and the chart takes the height it needs. On every surface, the mouse wheel scrolls the page and never zooms a chart.

Our context

VC dashboards are the overview an analyst or care manager scans on a large monitor before opening anything. The lists behind them are long: 40 or more providers, practices or measures in one ranking. That length is what tempts a team to put a scrollbar in the tile.

The rule

A dashboard tile never scrolls. It shows the top 5–8 rows, states how many are left, and links to the detail page.

  • Detail page: the chart takes its full height and the page scrolls.
  • Fixed-height panel that must stay in view: vertical inner scroll, with a sticky header, a row count and keyboard focus.
  • Zoom and pan: explicit controls on every surface. The plain mouse wheel always scrolls the page.

The deciding question is whether the reader needs the shape or every row. Shape → tile. Every row → detail page.

01 / Quick reference

Where the chart sits decides the scroll

Find the surface, then read across. Only one row allows a scroll region inside the page, and it comes with conditions.

Dashboard tile Never. Top 5–8 rows, a count of what's left, and "View all 40 →" to the detail page.

03 / The reasoning

Why the tile never scrolls

A dashboard exists to be read in one pass, and a scroll region breaks that pass.

1

A dashboard is read at a glance, on one screen

Few defines it as information "arranged on a single screen so the information can be monitored at a glance". A tile that scrolls hides part of its own answer.

2

A clipped tile reads as complete

Rows below the cut go unseen, and a 3px thumb is easy to miss. The care manager ranks providers from the seven they can see.

3

Nested scroll takes the page away

A wheel pass over a scrolling tile stops the page and moves the tile. A grid with several such tiles becomes hard to scroll at all.

4

The detail page has room for every row

It is one page with one scroll. The chart grows to fit its data, so the box, the second scrollbar and the trap all go away.

5

Wheel-zoom never hands the page back

Plain inner scroll passes to the page at its end. Wheel-zoom consumes every event, so the reader cannot scroll past the chart.

6

Every scroll region costs keyboard users

A region a keyboard can't focus hides its rows from keyboard users (WCAG 2.1.1). Horizontal scroll adds the second axis the breakpoints record rules out.

04 / In review

Where to draw the line in review

Scroll is fine when

  • The page itself scrolls on a detail page whose chart has taken its full height.
  • A fixed-height panel scrolls vertically beside content that must stay in view, with a sticky header, a visible row count, keyboard focus and an accessible name.

Reject in review

  • A scrollbar inside any dashboard tile. Cut to the top 5–8, state the remainder, and link to the detail page.
  • A tile cut off with no count of what's hidden. The reader takes the visible rows for the whole list.
  • An inner scroll box on a detail page where the chart owns the canvas. Let the chart grow and the page scroll.
  • Horizontal scroll in any chart region. Turn columns into horizontal bars, aggregate, or add a brush.
  • Zoom or pan on the plain mouse wheel, including a library default left switched on.
  • overscroll-behavior: contain on a chart region. It stops the page taking over at the region's end.
  • Two scrolling panels side by side. The reader can't tell which one the wheel will move.
05 / Precedent

Tools scroll by default, and the guidance pushes back

BI tools and chart libraries add scroll and wheel-zoom on their own. Dashboard theory, map platforms and usability research all keep the wheel for the page. Links are in the sources.

Stephen Few · Information Dashboard Design

One screen, monitored at a glance

Few's definition of a dashboard is the most important information "consolidated and arranged on a single screen so the information can be monitored at a glance". Content past the edge of the screen, or of a tile, falls outside that glance. VC's dashboard tiles follow this definition, and the detail page carries the rest.

one screen, one glance
Google · Maps Platform

Cooperative gestures keep the wheel for the page

In "cooperative" mode the user scrolls the page normally, without zooming or panning the map, and zooms with the controls. It is the default for a map inside an iframe.

wheel scrolls the page
Microsoft · Power BI

A scrollbar appears when categories overflow

When a categorical axis has more categories than fit in the visual, Power BI adds a scrollbar inside it. VC dashboards override that default with a top-N tile and a link.

default we override
Apache · ECharts

Wheel-zoom ships switched on

The inside data-zoom component sets zoomOnMouseWheel to true by default. Any VC chart built on it turns that off and adds explicit controls.

default we switch off
NN/g · Scrolljacking

Changing how the page scrolls frustrates users

NN/g defines scrolljacking as changing the speed or direction of page scrolling, and finds it causes more frustration than benefit. Their advice is to avoid it.

avoid scrolljacking
W3C · WCAG, with Deque axe

A scroll region must be reachable by keyboard

Axe's scrollable-region rule maps to WCAG 2.1.1: keyboard users must be able to focus the region or something inside it. Every scroll region we allow carries that cost.

focusable or unreachable
Synthesis

The pattern for tools like ours

For a VC dashboard on a large monitor, the tile shows the top of the list and links to the rest. The detail page scrolls as a page. The wheel never zooms. Where a library or BI tool defaults otherwise, we change the default.

tile summarises, page scrolls
